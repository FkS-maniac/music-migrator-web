# music-migrator (web)

Перенос музыкальной библиотеки между Spotify и Яндекс Музыкой — прямо в
браузере, без установки. Веб-версия [CLI-инструмента из тест-билда](../music-migrator-test-build):
та же логика — скоринговый матчинг (караоке/трибьюты отсекаются), журнал
прогресса с продолжением после остановки, обработка 429 и суточных квот
Spotify, dry-run.

## Что умеет

- **Яндекс → Spotify** и **Spotify → Яндекс**: лайки, плейлисты, альбомы, подписки
- **Лайки → отдельный плейлист** внутри одного сервиса
- **Экспорт** библиотеки в JSON/CSV и **импорт** из файла
- Прогресс сохраняется в браузере (localStorage): закрыли вкладку, исчерпали
  квоту — открыли позже и продолжили с места остановки, без дублей плейлистов

## Быстрый старт

### Spotify (работает напрямую, без прокси)

1. Зайдите в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard)
   → Create app.
2. В настройках приложения добавьте Redirect URI — тот, что показан на сайте
   в подсказке под полем Client ID (адрес этого сайта).
3. В настройках включите **Web API** (User Management не нужен) и добавьте
   свой аккаунт в **Settings → User Management** (Development mode: до 5
   пользователей, владелец — Premium).
4. Скопируйте **Client ID** в поле на сайте → «Подключить Spotify».

Авторизация — OAuth Authorization Code с PKCE: секрет приложения не нужен,
токен хранится только в вашем браузере.

### Яндекс Музыка (нужен свой мини-прокси)

Браузер не может обращаться к `api.music.yandex.net` напрямую — API не
отдаёт CORS-заголовки. Решение — ваш личный Cloudflare Worker (бесплатный
тариф, ~30 секунд на развертывание):

1. Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com) →
   Workers & Pages → **Create worker** → Deploy.
2. Откройте редактор кода (Edit code), вставьте содержимое
   [`worker/worker.js`](worker/worker.js) из этого репозитория → Save → Deploy.
3. Скопируйте адрес воркера вида
   `https://music-proxy.username.workers.dev` в поле «Адрес вашего прокси».
4. Получите токен: откройте
   [ссылку авторизации](https://oauth.yandex.ru/authorize?response_type=token&client_id=23cabbbdc6cd418abb4b39c32c41195d),
   войдите в Яндекс ID и скопируйте токен из адресной строки — вставьте в
   поле «OAuth-токен».

Токен проходит только через ваш собственный Worker и больше никуда не
сохраняется. Действует ~год, отзывается в Яндекс ID.

## Квоты Spotify (критично)

- Квота считается на аккаунт разработчика: ~**700 треков в сутки**
  (на каждый трек — один поиск + пакетные сохранения).
- При 429 `QUOTA_EXCEEDED` сайт сохранит прогресс и покажет время возврата —
  просто откройте его на следующий день и нажмите «Начать перенос» ещё раз.
- Перенос 7 000 треков ≈ 10 прогонов в разные дни. Это ограничение Spotify,
  обойти его легально нельзя.

## Матчинг

Каждый трек ищется в приёмнике (до 10 кандидатов), кандидаты оцениваются:
длительность ±3 с — 2 балла, совпадение артиста — 2, нормализованное
название — 1. Порог принятия ≥ 2; ISRC при наличии — приоритетнее скоринга.
Караоке-версии и трибьюты не проходят порог. Ожидаемо «не найдено» < 1–2 %
(региональные релизы, VK-эксклюзивы).

## Безопасность

- Только OAuth-токены, никогда логины и пароли.
- Токены хранятся в localStorage вашего браузера; для Яндекса запросы идут
  через ваш личный Worker.
- Кнопка «Сбросить прогресс» очищает журнал вкладки; удалить токены можно,
  очистив данные сайта в браузере.

## Структура

```
index.html          — интерфейс
js/spotify.js       — OAuth PKCE + Web API
js/yandex.js        — неофициальный API через прокси
js/matcher.js       — скоринговый матчинг (порт из Python)
js/transfer.js      — пайплайн: пачки, 429, отчёт
js/journal.js       — журнал прогресса (localStorage)
js/files.js         — экспорт/импорт JSON/CSV
worker/worker.js    — Cloudflare Worker (CORS-прокси Яндекса)
```
